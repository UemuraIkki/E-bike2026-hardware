# 担当D: CAN通信モジュール

トルクセンサとSTM32は、信号線を直接つなぐだけでは通信できない。両者の間にはCANトランシーバが必要であり、電源電圧が合っていても、ビットレートやIDが違えばデータは一つも読めない。担当Dは、この通信経路の設計・製作・検証を受け持った。

## 行った作業

最初に、トルクセンサとSTM32L476RGのbxCANを接続するモジュールを設計した。STM32は3.3Vロジックで動作するため、トランシーバにはSN65HVD230を用いる方針とした。MCP2551は5V動作であり、STM32へ直接接続する構成には使わない。

回路では、VCC、GND、TXD、RXD、CAN_H、CAN_Lを整理し、バス両端の終端抵抗を検討した。設計だけでなく、モジュールの製作、配線、電源確認、通信試験までが担当範囲である。

6月15日には、保管されていたCANトランシーバを流用できる可能性が見つかった。ただし、型番と電源電圧を確認できなければ採用はできない。外形やピン配置が似ていても、3.3V用と5V用の違いは回路の安全性に直結する。

物理層が正しくても、受信処理には別の情報が要る。CANビットレート、ID、標準・拡張フレーム、DLC、バイト配置、符号、スケールが分からなければ、受信した値をトルクへ変換できない。トルクセンサのゼロ点と既知荷重時の変化も、アシスト量を決める前に測定する必要がある。

## 作業の要点

- CAN通信方式とトルクセンサ仕様の調査
- SN65HVD230を用いた回路設計
- CANモジュールの製作と配線
- 3.3V電源、TXD、RXD、CAN_H、CAN_Lの確認
- 終端抵抗の検討
- bxCANのビットレート、ID、DLC、フィルタ設定の調査
- 無荷重・既知荷重時の受信値確認
- 配線断線、センサ停止、タイムアウト時の安全動作検討

## 到達点と残った課題

CAN通信モジュールの設計・製作・検証を進め、3.3V系トランシーバを使用する方針を定めた。一方、使用した現物の型番、回路図、終端抵抗、CAN_H/CAN_L波形、受信フレームはまだ資料が不足している。

受信できたかどうかだけでは、トルクセンサの検証としては足りない。既知の荷重に対して値がどのように変化し、通信が途切れたときにモータ指令を安全側へ戻せるか。その二つを記録して、CANモジュールはアシスト制御の入力になる。
