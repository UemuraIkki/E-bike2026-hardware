# 担当A: モータ制御・モータ位置Hall・全体管理

モータは、一度回れば完成という部品ではなかった。無負荷で回転できても、起動時の過電流、低速での位置推定、負荷を加えたときの逆回転が残る。E-bikeとして使うには、回転させることより、異常な回転を止めることの方が難しかった。

担当Aはモータ制御全般を受け持ち、プロジェクトの進捗管理と、車速Hall・CAN両担当の技術補助も行った。

## 行った作業

4月は、NUCLEO-L476RG、X-NUCLEO-IHM08M1、24V BLDCモータを接続し、MCSDK 6.4.2で制御環境を構築した。接続方向の誤りを修正し、まず速度制御で安定して回転させる方針を立てた。

5月以降は、速度指令、開始・停止、Fault処理を段階的に組み込んだ。起動ランプの電流目標が14.175AとなったときはOver Currentが発生したため、目標を約5Aへ下げた。ベンチ電源の電流制限が不足したときはUnder Voltage Faultが発生し、3A以上へ変更して改善した。

モータ位置検出用Hallセンサも担当Aの範囲である。3信号を確認し、Hall Profilingで電気角オフセット300°を得た。しかし、PA15とPB3がJTAGとHall入力で競合し、Speed Feedback Errorも安定運用を妨げた。デバッグ方式をSWDへ変更し、誤り回数、平均速度FIFO、入力フィルタを調整したものの、最終的な運用方式にはセンサレスFOCを選んだ。

速度制御の次に、RUN状態へ到達してからトルク指令へ切り替える処理を作成した。ところが、トルクモードは無負荷で5000rpm付近まで加速する可能性がある。そこで速度を監視し、設計目安3500rpmでトルクを制限する構成を検討した。

さらに、チェーンへブレーキや外力を加えると、推定角度が外れて逆回転方向へ加速する場合があった。速度推定の信頼性低下、逆回転、過速度を検出した場合はIq指令を0にするガードを追加した。モータを停止して再起動すると復帰できない場合があったため、RUN状態を保ったままトルク指令だけを0にする方式も試した。

## 作業の要点

- MCSDK・Workbenchによるモータ制御環境の構築
- 速度制御からトルク制御へ進む段階試験
- Over Current、Under Voltage、linker errorの原因切り分け
- モータ位置Hallの3信号確認とHall Profiling
- JTAGからSWDへの変更とSpeed Feedback Error対策
- トルクモードの速度監視、逆回転・過速度ガード
- 全体進捗の管理と、担当B・Dへの技術補助

## 到達点と残った課題

センサレスFOCでモータを回転させ、速度制御、トルク指令、安全ガードを試せる段階まで進んだ。一方、停止・低速では回転子位置を推定できず、強い負荷を加えたときの安定性も十分ではない。0rpmから安全にアシストする方法と、速度キャップを含む定量試験が残っている。

モータが回ることは確認できた。次に必要なのは、どの負荷条件でも意図した方向と速度を保てるという記録である。
